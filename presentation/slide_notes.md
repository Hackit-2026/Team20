## 1. 課題・背景(ストーリーの起点)

### 社会課題
- 日本の喫煙率は約15%、20代でも一定数。禁煙外来・アプリは多数あるのに継続率が低い
- 既存の禁煙アプリの typical パターン:記録 → 説教・警告 → うんざりして削除
- **インサイト: 「やめろ」と言われて人はやめない。命令・説教は行動変容に効きにくい**

### 発想の転換(ここが企画の核)
- 正論で殴るのではなく、**「なりたくない自分」をキャラクターとして見せる**
- 行動経済学でいう「現在バイアス」対策:将来の健康被害(遠い)を、キャラの見た目の変化(今ここ)に変換する
- キャッチコピー: **「説教しないアプリです。ただ、鏡を置くだけ。」**

【スライド化のコツ】既存アプリの失敗パターン(説教→削除)を1枚、発想の転換を1枚に分ける。
【審査員ウケ】「現在バイアスを可視化で克服する」と一言添えると、思いつきではなく行動科学に根ざした設計だと伝わる。

## 2. ソリューション(プロダクト概要)

### コアループ(1日1回)
1. 夜、リマインダー通知が届く「今日は何本吸った?」
2. ワンタップで本数を申告(+/−ボタン)
3. キャラクターが即座に反応(吸えば悪化、我慢すれば祝福)
4. 履歴・グラフで自分の推移を客観視

### キャラクター成長システム(最大の特徴)
- **21段階(S0〜S20)の姿変化**: 真っ白な健康キャラ → 黄ばみ → 目つき悪化 → 真っ黒な赤目モンスター
- **計算式: 成長度 = 前日から1ヶ月前までの累積本数(1本=1段階、上限20)**
  - 「今日ゼロ本でも過去の蓄積は消えない」= タバコの害の遅効性をゲームメカニクスで表現
- キャラをタップすると成長度に応じたセリフ:
  - 健康時「毎日吸ってなくてうれしいよ!」「今日も空気がおいしい!」
  - 中期「のどがイガイガする…」「ライター…ライターどこ…」
  - モンスター化「モクをよこせェェ!!」「…まだ、戻れるかな…?」
- 羽ばたきアニメーション(パーツ分割画像による常時アニメ)

### 罰の設計(ペナルティシステム)
- 週2本以上で「重度ペナルティ」発動:
  - **スマホのシステム壁紙が警告壁紙に強制変更**(アプリの外まで罰が追いかける)
  - 60秒間の操作ロック画面(回避防止2重ロック付き)
  - 他アプリを開いてもオーバーレイ警告が表示される
- 記録をサボった日は自動でペナルティポイント加算(捏造・放置を許さない)

### 報酬の設計(アメの演出)
- 本数を減らす(−ボタン)と**パチンコ大当たり風エフェクト**:
  金色フラッシュ点滅 + 回転する放射光 + 紙吹雪22粒 + 「🎰大当たり!!」がバネアニメで飛び出す
- 「我慢 = 地味で辛い」を「我慢 = 気持ちいい」に反転させる

### 可視化
- 履歴画面: 1週間/1ヶ月切り替えの棒グラフ
- 日別ログ: **吸った本数分の🚬絵文字を並べるピクトグラム**(数字より直感的に「多い」と分かる)
- 0本の日は「🌿 クリーンな1日!」表示で対比

### 目標の段階的削減
- Mode 1: 今週の平均本数 ÷ 1.5 を次の目標に(無理のない漸減)
- Mode 2: いきなりゼロ本目標(ストイック派向け)

【スライド化のコツ】機能を全部並べない。「キャラ(鏡)」「罰(壁紙)」「報酬(大当たり)」の3本柱で見せて、残りは1枚のまとめ表に。
【審査員ウケ】「罰と報酬の両輪設計」「アプリの外まで罰が届く(壁紙・オーバーレイ)」は他チームと差別化できる独自性。

## 3. 技術構成

### スタック
| レイヤ | 技術 | 選定理由 |
|---|---|---|
| UI | Jetpack Compose(Kotlin) | 宣言的UIで2日間の高速試作に最適 |
| 設計 | MVVM + Repository | ロジック/データ/UIの分離。チーム分業しやすい |
| データ | SharedPreferences + kotlinx.serialization(JSON) | ハッカソン規模ではDB不要。シンプルさ優先 |
| 通知 | AlarmManager + BroadcastReceiver | 毎日指定時刻の正確な発火。端末再起動後の再予約も対応 |
| ペナルティ | WallpaperManager / SYSTEM_ALERT_WINDOW(オーバーレイ) / UsageStats | 「アプリの外への罰」を実現する低レイヤAPI |
| アニメ | Compose Animation(Animatable / spring / Canvas) | 物理ベースのバネ・放射光・紙吹雪を外部ライブラリなしで実装 |

### アーキテクチャ図(スライド用に描く)
```
[HomeScreen / HistoryScreen / GoalSettingScreen / DebugScreen]  ← Compose UI
                    ↕ StateFlow
              [MainViewModel]                                    ← 状態管理
                    ↕
               [AppRepo]                                         ← データ層(JSON永続化)
                    ↕
   [Reminder/AlarmManager] [WallpaperManager] [OverlayService]   ← OS連携
```

### こだわりの実装ポイント(技術アピール用)
1. **キャラ成長ロジックの仕様化**: 「前日から30日間の累積、今日は含めない」— 今日の申告で即変わるのは"今日の演出"、キャラの姿は"積み重ねの結果"という役割分担
2. **パチンコエフェクト**: 1本の進行度変数(0→1)から、フラッシュ(前半のみ)・放射光の回転・紙吹雪の放物線(初速−重力)・フェードアウト(最後の30%)を全て導出。タイミング管理が破綻しないゲーム演出の定石
3. **テーマのライト固定**: ダークモード端末で入力欄が白飛びするバグを発見→ 全端末で同一表示になるようライトテーマ固定+dynamicColor無効化(デモの安定性重視)
4. **タブレット対応**: コンテンツ最大幅560dp+中央寄せで、大画面でも間延びしないレスポンシブ設計

【審査員ウケ】「外部ライブラリなしで演出を全部Composeで書いた」は技術力の証明になる。

## 4. チーム開発プロセス(企業・メンターが一番見るところ)

### 役割分担
| 担当 | 役割 | 主な成果物 |
|---|---|---|
| A(ryuuzinnraika) | コアロジック・データ・Git管理 | Repo / ViewModel / ペナルティ / サーバー試作 |
| B(Ryousuke2099) | 画面UI・キャラデザイン | 各画面 / キャラ画像105枚 / 羽ばたきアニメ |
| C→開発担当(kotakota914) | 通知→キャラ機能・UI改善・発表 | 通知 / 21段階キャラ / ピクトグラム / エフェクト / スライド |

### Git運用ルール(実際に守ったもの)
- 他人の担当ファイルは触らない(またぐ時は一声)
- プッシュ前に必ずプル(--rebase)
- 機能はブランチで開発 → PRでレビュー → マージ
- 依存関係(build.gradle)の追加は1人に集約

### 実際にあった連携エピソード(ストーリーとして強い)
1. **機能のリレー**: Cが作った通知エンジン(Reminder.kt)を、Aがオンボーディングに統合。Cが作ったキャラ表示を、Bが羽ばたきアニメに進化させた(コミットログに「teammateのCharacterSectionを採用」が残っている)
2. **コンフリクト解決**: MainActivityで衝突 → 設計ルール(担当ファイル制)に従いA版を採用、自分のUIは別ファイルへ切り出して解決
3. **バグ発見→即修正→全員に配布**: タブレット実機テストでダークモード表示バグを発見、原因特定(テーマ追従)→修正→両デバイス配布まで30分

### 検証体制
- エミュレータ(Pixel / API 36)+ 実機(Galaxy Tab S7)の2環境
- スクリーンショットで各機能の動作証跡を残しながら開発
- デバッグ画面を自作(日付指定データ投入 / 30日デモデータ / ペナルティ即発火 / 全リセット)→ **デモ用の裏コマンドとして発表でも活用**

【スライド化のコツ】「役割分担表」+「連携エピソード1つ」で1枚。コミットログのスクショ(teammateのCharacterSectionを採用)を貼ると生々しくて良い。
【審査員ウケ】ハッカソンで「コンフリクトをルールに基づいて解決した」「実機で検証した」チームは少ない。プロセスの話は企業メンターに最も刺さる。

## 5. デモシナリオ(3〜5分想定)

1. **つかみ(30秒)**: 「禁煙アプリ、続いたことありますか?」→ 説教されて消した経験に共感を取る
2. **オンボーディング(20秒)**: 設定が数タップで終わることを見せる
3. **ライブデモ①悪化(60秒)**: 壇上で+ボタン連打 → キャラが白→緑→黒モンスターに変化(会場の笑いどころ)
4. **ライブデモ②罰(40秒)**: ペナルティ発動 → 壁紙が変わる・ロック画面・他アプリにも警告(「アプリの外まで追いかけます」)
5. **ライブデモ③報酬(30秒)**: −ボタン → パチンコ大当たり演出(「我慢が気持ちいいアプリです」)
6. **履歴画面(20秒)**: 🚬ピクトグラム「数字じゃなくて、量で見せます」
7. **通知(20秒)**: テスト通知ボタンで発表中にその場で通知を鳴らす
8. **締め(20秒)**: 「説教しないアプリです。ただ、鏡を置くだけ。」

### デモ用裏コマンド(デバッグ画面)
- 過去30日デモデータ一括投入 → キャラ即モンスター化
- 昨日に3本投入 → ペナルティ即発火
- ペナルティロックはデバッグ用に10秒短縮済み(⚠️本番ビルドでは60秒に戻す)

【スライド化のコツ】デモ中はスライドを「デモ中」の1枚で止めておく。失敗時の保険としてスクリーンショット/録画GIFをスライドに仕込んでおく。

## 6. 苦労した点と学び(質疑・メンター面談用)

1. **Gitコンフリクト**: 同一ファイルの並行編集で衝突 → 担当ファイル制+切り出しで解決。「ルールを事前に決めておく」重要性を学んだ
2. **ダークモードバグ**: 実機テストで初めて発覚(エミュレータはライトモードだった)。「多様な環境での検証」の重要性
3. **エミュレータ不安定問題**: クラッシュ頻発 → コールドブート+ソフトウェア描画で安定化。環境トラブルの切り分け経験
4. **仕様の高速な変化**: 2日間でポイント制→本数制、4段階→21段階など仕様が数回転。「小さく作って壊す」MVP思考で追従
5. **チーム間のコード統合**: 自分の機能が他人にリレーされて成長する体験(通知→オンボ統合、キャラ→羽ばたき)

## 7. 今後の展望(ビジョンで締める)

- **回復システム**: 吸わない日が続くとキャラが1段階ずつ健康に戻る(「もう手遅れ」ではなく「今からでも戻れる」希望の設計)← 行動科学的に最重要の次施策
- **ペナルティ中の妨害キャラ**: ロック画面でモンスターが暴れ回る演出(罰のエンタメ化)
- **節約金額の換算表示**: 「我慢したタバコ代でラーメン◯杯」
- **キャラによる通知ジャック**: キャラの状態で通知の口調が変わる
- **ウェアラブル連携構想**: スマートウォッチの心拍・SpO2で喫煙検知(要件定義に記載済み)
- **データ**: 匿名統計で「みんなの平均減煙カーブ」を見せる社会化

【スライド化のコツ】展望は「すぐやる(回復システム)」「中期(通知ジャック等)」「夢(ウェアラブル)」の3段で見せると現実感が出る。

## 8. 想定Q&A(審査員対策)

- **Q: 吸う人がわざわざ記録する動機は?** → A: 記録しないと自動ペナルティが積まれる設計+夜の通知1タップで手間を最小化。さらにキャラの変化・大当たり演出が記録自体を娯楽にする
- **Q: 虚偽申告(0本と嘘をつく)への対策は?** → A: 現状は性善説+「キャラは自分の鏡なので嘘をつくと意味がなくなる」という設計思想。将来はウェアラブル検知で補完
- **Q: なぜ本数ベース?タール量は?** → A: 初期案はタール量×本数だったが、入力の手間と分かりやすさを優先して本数に一本化(MVP思考の意思決定として語れる)
- **Q: 既存アプリとの違いは?** → A: ①説教しない(反面教師の可視化)②罰がアプリの外に出る(壁紙・オーバーレイ)③我慢に即時報酬(大当たり演出)の3点
- **Q: 21段階の根拠は?** → A: 1本=1段階の直感的な対応関係+1ヶ月累積の上限として現実的な20本。1本の重みが視覚で分かる

## 10. 30秒進捗報告(口頭用スクリプト)

> 話す速度の目安: 1分300字 → 30秒 ≈ 150〜170字。以下は本番でそのまま読める長さ。

### 基本版(約160字 / コンセプト重視)

「チーム20『Yo Say 酒場』です。私たちは"説教しない禁煙アプリ"を作っています。
吸った本数を記録すると、キャラクターが21段階でモンスターに変わっていく、反面教師型のアプリです。
現在、記録・キャラ育成・ペナルティ・通知などMVPの主要機能は実装済みで、実機タブレットでの動作確認も完了しています。
残りはデモ演出の仕上げと発表準備です。」

### 数字アピール版(約170字 / 進捗の量を見せたいとき)

「チーム20です。反面教師型の禁煙アプリを開発中で、開始から2日で91コミット、主要機能はすべて実装済みです。
具体的には、本数記録、21段階のキャラ変化、壁紙が変わるペナルティ、リマインダー通知、履歴グラフまで動いています。
エミュレータと実機の両方で検証済みで、mainへの統合PRもレビュー待ちです。
残タスクは演出の磨き込みと発表リハーサルです。」

### 困りごと共有版(メンターに助言が欲しいとき用の締め差し替え)

末尾を「残りは発表準備ですが、**デモ中にペナルティ演出を確実に発火させる段取り**に悩んでいます。アドバイスいただけると嬉しいです。」に差し替える。
※進捗報告は「やったこと→今の状態→次やること(+困りごと)」の3点セットで話すのが定石。

### 話し方のコツ
- 最初の1文でチーム名とコンセプトを言い切る(聞き手が頭にフックを作れる)
- 「実装済み」「検証済み」「レビュー待ち」など**状態を表す言葉**で締めると進捗が伝わる
- 30秒指定なら25秒で終わる原稿にしておく(本番は必ず伸びる)
