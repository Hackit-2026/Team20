# アプリ総合要件定義書 (Requirements Definition - 最新確定版)

本ドキュメントは、アプリ「ヤニモグラ」の全画面配置・判定ロジック・レイアウト・ポイント計算・放置ペナルティ・リアルタイムコミュニティ通信・通知制御・閲覧履歴グラフ・SQLite (SQL) データベース管理についての最新かつ完全な仕様書です。
※本ドキュメントでは「AI」「人工知能」という表現を完全に排除し、本物の人間・キャラクター（専属メンバー）として定義しています。

---

## 1. アプリ概要 & コアコンセプト
- **アプリ名**: **ヤニモグラ (YANI-GOTCHI)**
- **コンセプト**: 「タバコを促進してキャラを育てる反面教師育成 ＆ コミュニティ応援アプリ」
- **コア体験**:
  - タバコを吸った本数に応じて、真っ白で健康なキャラクターが「喫煙し始め」→「ヘビースモーカー」→「ヤニモンスター」へとすくすく（悪魔的に）変化。
  - 0本（我慢した日）にはキャラクターが**禁断症状（ヤニ切れ）**で必死におねだり！
  - 1日通知を放置して入力しないと、ペナルティでポイントが大量強制加算されモンスター化！
  - アプリ内のタイムラインでは、ユーザーや仲間の投稿に対し、**4人の専属メンバー（熱血仲間・修造 / ツンデレ友達・アスカ / Dr.ヘルス / ヤニモグラ）が一斉に「頑張れ！」「耐えろ！」と温かい応援コメント**をリアルタイムで返信！

## 2. ポイント計算 ＆ 放置ペナルティルール（0〜200pt制）

### 2-1. ポイント計算公式 (`吸った本数 - 1 pt`)
- キャラクターの悪化・成長状態を **0pt 〜 200pt** の固定範囲で管理（`0 <= points <= 200`）。
- **1日の基本ポイント計算式**: **`ポイント変化量 = (吸った本数 - 1) pt`**
  - **0本吸った日**: `0 - 1 =` **`-1 pt`** (禁断症状演出発火・健康状態へ戻る)
  - **1本吸った日**: `1 - 1 =` **`0 pt (±0)`** (現状維持)
  - **2本吸った日**: `2 - 1 =` **`+1 pt`** (ポイント加算・キャラ成長)
  - **3本吸った日**: `3 - 1 =` **`+2 pt`**
  - **N本吸った日**: **`+(N - 1) pt`** (吸えば吸うほどポイントが蓄積)

### 2-2. 🚨 1日通知放置ペナルティ仕様
- **ペナルティ発生条件**: 1日の終わり（夜24:00または翌日）までに通知を無視し、メイン画面での確定保存を行わずに放置した場合。
- **ペナルティ加算量**: **`+ (1日の目標本数) pt`**
  - 例: 1日の目標本数が **10本** のユーザーが1日放置した場合、ペナルティとして **`+10 pt`** が強制加算され、ヤニモグラが一気にモンスター化・暴走する仕様。

### 2-3. 10ptごとの画像・ビジュアル変化（全20段階）
- **10ポイントごと**にキャラクターの画像・見た目・形態が変化（全20段階）。

## 3. 🌐 コミュニティタイムライン ＆ リアルタイム反応システム

### 3-1. 禁断症状演出（ポイント下降・0本の日）
- **演出条件**: 0本の日（-1pt）やポイント下降中。
- **演出内容**: ヤニモグラがヤニ切れを起こし、必死なおねだり・焦りセリフを発する。
  - 😈「おい！口が寂しすぎて死にそうだぞ！1本でいいから吸ってくれ！」

### 3-2. 専属メンバーによるリアルタイム応援コメント双方向通信
- **HTTP双方向通信連携**:
  - ユーザーのつぶやき・我慢ログ投稿を Python サーバー (`POST /api/posts`) へ送信。
  - サーバー経由の LM Studio (`http://192.168.25.42:11434`, モデル: `google/gemma-4-12b-qat`, `/v1/models` 自動検出) 実推論により、4人のメンバーが即座に短い反応コメントを生成して送り返す。
- **4人の専属メンバーペルソナ**:
  - **熱血仲間・修造 (🔥)**: 「あきらめるな！気合で乗り越えろ！！🔥」
  - **ツンデレ友達・アスカ (😳)**: 「べ、別に心配してないんだからね！でも…今日我慢できたのは偉いわよ…」
  - **Dr.ヘルス (👨‍⚕️)**: 「医学的にも最初の3日が山場です。素晴らしい我慢です！」
  - **ヤニモグラ (👹)**: 「おい！我慢するな！吸って俺を育てろ〜！」

## 4. 画面レイアウト & 操作仕様（画面別詳細）

### 4-1. オンボーディング画面 & リセット初期化仕様
- **目標本数設定の初期値**: 設定画面を開いたとき、およびデータリセット時の1日の目標本数初期値は `10本` とする。

### 4-2. メイン画面 (HomeScreen) レイアウト ＆ 操作仕様
- **今日の至福の本数（表示本数）の動的初期値設定**:
  - メイン画面の「本日の本数」の初期表示値は、**ユーザーが初めに設定した「1日の目標本数 (10本など)」をそのまま動的初期値**とする。
- **減算（下げる方向）への心理的調整設計**:
  - 設定された目標本数を初期値とし、我慢・減煙するほど `+` / `-` ボタンで**数値を下げる方向に調整**することで、ユーザーが「減煙・達成できている感（やってる感）」を強く実感できるUI設計とする。
- **配置レイアウト (画面上寄せ最適化)**:
  - **左上ボタン**: **「履歴ボタン（履歴・カレンダー画面へ）」**
  - **右上ボタン**: **「デバッグボタン（DebugScreenへ）」**
  - **中央キャラクター画像**: キャラクター画像を上に寄せて配置。
  - **確定保存ボタンの1日1回制限**: 「確定して保存」ボタンは『1日に1回』のみ押せる制限。
  - **画面底部**: **「⏳ 残り期間: 〇〇日」** を画面下に確実に表示。

### 4-3. 📊 閲覧履歴画面 (CalendarScreen / 履歴) (追加要件)
- **アクセス**: メイン画面の**「左上ボタン」**から遷移。
- **週・月切替 棒グラフ表示**:
  - **「1週間分 (過去7日間)」** および **「1ヶ月分 (過去30日間)」** をタブ切り替えで可視化棒グラフ描画。
  - 日別の本数表示（目標本数ガイドライン線を含む）および日付別ログリストを表示。

### 4-4. 🔔 リマインダー通知制御仕様
- **確定保存済み時の自動通知スキップ**:
  - 本日分の本数がすでに確定保存済みである場合、リマインダー通知は発火せず**自動スキップ（キャンセル）**される。

### 4-5. デバッグ画面 (DebugScreen) 仕様
- **アクセス**: メイン画面の**「右上ボタン」**から遷移。
- **サーバーURL自由変更**: デバッグ画面内にサーバーURL入力欄（初期値: `http://192.168.25.42:8000`）を設置し、動的にアドレスを変更・保存可能。
- **スマートウォッチ模擬テスト**: スマートウォッチの動作検知・SpO2・10分＝1本換算テストはすべてデバッグ画面のテストボタンでカバー。
- **リザルト結果画面**: `ResultScreen` へのアクセスボタンをデバッグ画面の中に集約。

## 6. SQL データ構造仕様 (`server/schema.sql`)
```sql
CREATE TABLE posts (
    post_id TEXT PRIMARY KEY,
    author TEXT NOT NULL,
    is_npc INTEGER NOT NULL DEFAULT 0,
    text TEXT NOT NULL,
    timestamp TEXT NOT NULL
);

CREATE TABLE comments (
    comment_id INTEGER PRIMARY KEY AUTOINCREMENT,
    post_id TEXT NOT NULL,
    name TEXT NOT NULL,
    avatar TEXT NOT NULL,
    comment TEXT NOT NULL,
    timestamp TEXT NOT NULL,
    FOREIGN KEY (post_id) REFERENCES posts(post_id) ON DELETE CASCADE
);
```
